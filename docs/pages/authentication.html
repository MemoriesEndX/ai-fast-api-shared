Authentication & Security

The Shared AI Service utilizes API Key Authentication and Strict Multi-Tenant Access Validation.

Authentication Headers

Every non-health API endpoint requires the X-API-Key request header (or Authorization: Bearer <key>).

Header NameFormatExample Value
X-API-Key String owl-secret-api-key
Authorization Bearer Token Bearer owl-secret-api-key

Multi-Tenant Isolation

The system validates that the client application identity matches the request payload application parameter:

  • If X-API-Key: owl-secret-api-key is used, the request payload application MUST be "owl".
  • If X-API-Key: hr-corner-secret-api-key is used, the request payload application MUST be "hr-corner".
  • Mismatched requests will be rejected immediately with 403 TENANT_ACCESS_DENIED.

Authentication Error Responses

Unauthenticated or mismatched tenant requests return standardized JSON error objects:

401 Unauthorized Response 
{
  "error": {
    "code": "UNAUTHORIZED",
    "message": "Invalid or missing API key.",
    "status": 401
  }
}
