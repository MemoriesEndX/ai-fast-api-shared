Phase 17 Production

Production Observability & Monitoring

Structured logging, distributed request ID tracing, health and readiness probes, and real-time operational metrics for OWL, HR Corner, and Public Chat.

1. Request ID Tracing

Every incoming HTTP request is assigned or traced with a unique X-Request-ID identifier.

  • Client Propagation: If a client includes X-Request-ID in request headers, the system validates and propagates it throughout the request lifecycle.
  • Auto-Generation: If omitted, a UUIDv4 string is automatically generated.
  • Response Header: The service attaches X-Request-ID and X-Process-Time to every response.
HTTP Response Headers 
HTTP/1.1 200 OK
Content-Type: application/json
X-Request-ID: e89a42f1-678b-4c22-b91a-821213f569a1
X-Process-Time: 4612.45ms

2. Operational Health & Readiness Probes

The service provides dedicated health probes for container orchestrators (Kubernetes / Docker Swarm / Compose):

GET /health Liveness Probe

Fast process liveness check confirming service container is running.

GET /ready Readiness Probe

Dependency readiness check evaluating Qwen 2.5 LLM backend and Qdrant Vector Engine availability.

3. Operational Metrics Endpoints

Real-time Prometheus exposition and JSON snapshot metrics:

  • GET /metrics — Prometheus text exposition format (Content-Type: text/plain; version=0.0.4)
  • GET /metrics/json — JSON metrics snapshot

4. Secret & Privacy Protection Audit

Zero Data Leakage Policy: API Keys (X-API-Key), Bearer tokens, Passwords, User HR/LMS private profiles, and raw document contents are strictly redacted and omitted from production logs and metric labels.
